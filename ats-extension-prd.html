PRD: ATS Resume Scorer — Chrome Extension

Version: 1.0  |  Date: May 2026  |  Status: Draft

1. Problem

Job seekers apply to roles without knowing if their resume matches the job description. ATS systems reject resumes before a human sees them. There is no fast, in-browser tool to score a resume against a live JD without copying text around or uploading to sketchy third-party sites.

2. Goal

A Chrome extension that sits on any job posting, scrapes the JD, scores the user's stored resume against it instantly, and optionally gives AI-powered feedback and a tailored resume — all without leaving the tab.

3. User Flow

  1. User opens any job posting (LinkedIn, Naukri, Greenhouse, Lever, etc.)
  2. Clicks the extension icon — popup opens
  3. Resume already stored from a previous upload, or user uploads/pastes now
  4. Extension scrapes the active tab's JD text via content script
  5. Runs TF-IDF + keyword matching locally — shows score instantly
  6. User optionally clicks "Get AI Feedback" or "Tailor Resume" (API-powered)

4. Feature Tiers

Tier 1 — Instant Score (Free, Offline)

  • Scrape JD text from current tab
  • Parse stored resume (PDF via pdf.js or pasted text)
  • TF-IDF keyword extraction on JD
  • Keyword overlap scoring against resume
  • Score out of 100 with missing keywords list
  • No API key needed. Runs entirely in browser.

Tier 2 — AI Feedback (Claude API, On-Demand)

  • "Get AI Feedback" button — only called when clicked
  • Sends resume text + JD text to Claude API
  • Returns: why the score is what it is, top 3 things to fix, priority keyword gaps
  • Requires user to enter API key once (stored in chrome.storage.local)

Tier 3 — Tailored Resume (Claude API, On-Demand)

  • "Tailor My Resume" button
  • Claude rewrites bullet points, summary, skills order to match JD
  • Diff view: original vs tailored per section
  • Download as PDF via jsPDF (in-browser, no server)
  • Uses same API key as Tier 2

5. Scoring Logic (Tier 1)

Keyword Extraction from JD

  • Strip HTML, lowercase, remove stopwords
  • TF-IDF on remaining tokens to find high-signal keywords
  • Also extract tech terms via simple regex patterns and a curated skills dictionary

Score Formula

  • 60% — Keyword overlap (how many JD keywords appear in resume)
  • 25% — Skills section match (exact + fuzzy match on skills list)
  • 15% — Job title / role alignment

Output

  • Score: 0–100
  • Matched keywords
  • Missing keywords
  • Match % per section

6. Technical Architecture

Extension File Structure

/extension
  manifest.json         Manifest V3
  popup.html            Extension popup UI
  popup.js              UI logic, scoring calls
  content-script.js     Scrapes JD from active tab DOM
  background.js         Service worker (minimal)
  scorer.js             TF-IDF + keyword matching logic
  resume-parser.js      pdf.js integration, text extraction
  ai.js                 Claude API calls (Tier 2 + 3)
  pdf-export.js         jsPDF resume download
  /lib
    pdf.js              Mozilla PDF.js (lazy loaded)
    jspdf.min.js        jsPDF for export

Data Storage (chrome.storage.local)

{
  "resume_raw_text": "...",
  "resume_structured": { name, summary, skills[], experience[], education[] },
  "api_key": "sk-ant-...",
  "resume_vault": [{ job_title, date, tailored_resume }]
}

JD Scraping Strategy

  • Primary: target known selectors for LinkedIn, Naukri, Greenhouse, Lever, Workday
  • Fallback: grab all visible body text, strip nav/header/footer via heuristics
  • Manual fallback: user highlights JD text and triggers scan via right-click context menu

Resume Input Methods

  • Upload PDF → parsed via pdf.js → stored as raw text + structured JSON
  • Paste plain text → stored directly
  • Persists across sessions until user replaces it

7. Popup UI Screens

Screen 1 — No Resume Stored

  • Upload PDF button
  • Or paste resume text area

Screen 2 — Resume Stored, Ready to Scan

  • Resume name + "Replace" link
  • "Scan This Job" button (primary CTA)

Screen 3 — Results

  • Score: large number (e.g. 67/100)
  • Matched keywords
  • Missing keywords
  • "Get AI Feedback" button (Tier 2)
  • "Tailor My Resume" button (Tier 3)

  • Narrative explanation of score
  • Top 3 fixes ordered by impact

  • Section-by-section diff view
  • Copy section buttons

Settings

  • API key input + save
  • Clear stored resume
  • View resume vault

8. Resume Vault

Every time a resume is tailored, save a copy with job title + date as key in chrome.storage.local. User can view past tailored versions and re-download. No external DB needed. Cap at 20 entries.

9. Risks and Mitigations

Risk Severity Mitigation
JD scraping fails on unknown job sites High Fallback to full body text grab. Manual selection via context menu.
PDF parsing fails on complex resume layouts Medium Fallback to plain text paste. Show clear error message.
TF-IDF misses jargon and acronyms Medium Maintain a curated tech skills dictionary for exact matching alongside TF-IDF.
API key security Medium chrome.storage.local is sandboxed per extension. Document clearly to user.
chrome.storage.local 10MB size limit Low Cap vault at 20 entries. Prompt user to clear old ones.

11. Out of Scope (v1)

  • Multi-resume management
  • Backend or user accounts
  • Firefox / Safari support
  • Cover letter generation
  • Application tracking

12. Success Metrics

  • Tier 1 score loads in under 2 seconds on any job page
  • Scraping works on LinkedIn, Naukri, Greenhouse, Lever out of the box
  • PDF parse succeeds on 90%+ of standard resume formats
  • Tailored resume downloads without a server call
